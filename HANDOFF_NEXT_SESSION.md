## Architecture & patterns established — don't relitigate these

- **Schema + pure-engine split, for anything AI-generates.** A Pydantic model for internal validation, a separately hand-rolled raw JSON-schema dict for what Claude tool-calling / Gemini's `responseSchema` actually see (never `model_json_schema()`), and a **pure, network-free, unit-testable expansion function** that turns AI-authored semantic content into fully-resolved render data. This is the shape of `motion_schema.py`/`motion_engine.py` and `mind_map_schema.py`/`mind_map_engine.py` both.
- **Gemini schema gotchas:** `type` must never be an array/union — use a sibling `"nullable": true` instead. Recursive/self-referencing schemas (`$ref`) are unverified against a live Gemini call from this sandbox. There's a permanent structural test (`TestGenerationSchemaStructure` in `test_mind_map_engine.py`, equivalent in `test_motion_engine.py`) that walks the schema tree checking for both mistakes — extend it, don't bypass it, for any new schema (this pattern was reused correctly this session for the new `audio` field — see below).
- **Three-path credential model:** BYOK header / server-key-with-its-own-quota / manual-paste-mode. Shared credential-resolution pattern and `X-Client-Id` anonymous device identifier.
- **Byte-sync requirement:** any prompt duplicated in both `api/index.py` (Python) and a JS mirror (`motion-api.js`, `mind-map-doc-api.js`) must be re-verified byte-identical after every edit — extract Python's actual output with a placeholder, splice into the JS template literal via a script, diff the two. **Do not hand-retype.** Re-used and re-verified this session for `buildMotionManualPrompt()`.
- **Few-shot examples matter more than more rules.** A fully worked, schema-validated example is the highest-leverage lever for generation prompt quality — confirmed repeatedly now, including this session (the shared `_MOTION_EXAMPLE_JSON` now also demonstrates audio cues, re-validated end to end after editing).
- **`expand_script()`/`expand_mind_map()` must run before anything reaches the player.** The player expects fully-resolved keyframes, not AI-authored shorthand. Feeding it raw source data doesn't error — it just renders wrong.
- **`UPCOMING_FEATURES.md` gets updated in the same commit as any real change.** Hard project convention, followed without exception this session.
- **PAT hygiene:** John provides a PAT per chat, reused across the whole session for velocity — his call. Mention the one-time-use norm once per new chat, then don't repeat it on every push. Embed in the remote URL only for the actual push, scrub back to plain HTTPS immediately after, check `git log HEAD..origin/main --oneline` before every push.
- **Verification discipline — the actual house style:** unit tests with real assertions; live HTTP requests against a running local server (fresh process per test run — background processes don't survive across separate sandbox tool calls); Playwright screenshots for anything visual, driven through the *real* app's actual navigation (real `pointerdown`+`pointerup` pairs, not synthetic `.click()` — a synthetic click has previously failed to reproduce real bugs, e.g. the Help TOC hash-router bug from an earlier session); pixel-level/timing-level inspection, not just "a screenshot looked fine" (this session: instrumenting the real `AudioContext.createOscillator` to prove tones actually fired with correct timing, not just that no exception was thrown). This session alone caught: a wrong test assertion in my own first draft of a new test (traced through the actual behavior rather than assuming my expectation was right), a genuinely stale `DB version is 9` assertion left over from an earlier session's DB_VERSION bump, and a real gap where `motion-test.html`'s dev harness would have silently never played audio cues because it never primed `sound.js`'s enabled-cache.

## Recurring lessons, this session, worth internalizing

- **A synthetic Playwright `.click()` can miss real timing/state issues that a real `pointerdown`+`pointerup` pair or a real button click catches.** Used real interaction throughout this session for exactly this reason (learned the hard way in an earlier session with the Help TOC bug).
- **When writing a new test, don't assume your first-draft expectation is correct — trace through the actual logic.** This session's own `test_motion_player_audio.mjs` had a wrong assertion in its first draft (expected only 1 tick-refire after a coarse single-frame jump past duration; traced through and found the real, correct behavior fires all cues before duration in that pass) — the test was wrong, not the code. Verify your test's expectations as carefully as you verify the code.
- **A dev/instrumentation page that never imports the app's own init code can silently misrepresent real behavior.** `motion-test.html` never called `initSoundSetting()`, so `sound.js`'s enabled-cache defaulted to `false` and stayed there forever on that page — audio cues would have appeared broken on the one tool built specifically to test them, when the actual bug was a missing init call, not the cue logic.
- **A stale test assertion left over from an earlier change can mask real regressions.** `test_motion_frontend.mjs` still asserted `DB version is 9` after an earlier session's Mind Map v2 work bumped `DB_VERSION` to 10 — caught only by actually running the suite and reading the failure, not by assuming a passing test file was still accurate. Fixed on sight since it was one line, rather than left for later.
- **Trace an edge case through to its actual consequence before dismissing it as unlikely.** The camera fly-to's two edge-case fixes (destroy-mid-flight, new-gesture-mid-flight) weren't hit live — they were found by asking "what happens if..." and following the code path through, which is cheaper than finding them from a bug report later.
- **When instrumentation shows an unexpected extra event, trace it rather than assuming it's a bug in the new code.** The onboarding audio test initially showed 11 oscillator calls instead of an expected ~10 — tracing the timing pattern showed the extra one was an unrelated UI navigation sound captured in the same window, not a timing bug in the new cues.

## Tools & resources, as used this session

- Local backend: `cd api && MOTION_SERVER_CLAUDE_KEY="dummy-for-local-test" python3 -m uvicorn index:app --port <port>` — start and use in the same tool call; background processes don't survive across separate sandbox invocations. Use a fresh port per run if a prior one might still be bound.
- Static file server for full-stack Playwright testing: `python3 -m http.server <port> --directory public` (spawned from within the Playwright script itself via `child_process.spawn`, killed at the end of the same script) — no backend needed for anything that's pure IndexedDB + canvas/DOM, which covered every visual verification this session.
- Playwright: `chromium.launch({ executablePath: '/opt/pw-browsers/chromium-1194/chrome-linux/chrome' })`. Used for: seeding real IndexedDB data via the app's actual `db.js` functions (`addDeck`, `saveManualCard`, `updateCardAfterReview`, `saveSetting`), real pointer/button interaction (not synthetic `.click()` where timing/state mattered), instrumenting real Web Audio (`AudioContext.prototype.createOscillator`) to prove sounds actually fired with correct relative timing, and screenshot sequences across an animation/playback to confirm gradual visual change rather than an instant cut.
- **SPA navigation gotcha, hit this session:** Playwright's `addInitScript()` only re-injects on a fresh document load. This app is a single-page app — internal route changes are same-document hash changes, not reloads — so `addInitScript()` silently never fires for anything injected before an in-app `location.hash = '#/...'` change. Fix: inject instrumentation via `page.evaluate()` right after the *initial* full page load, before any hash navigation, and navigate via `page.evaluate(() => { location.hash = '#/...'; })` rather than a second `page.goto()` (which would trigger a real reload and wipe the instrumentation).
- `pip install pydantic fastapi uvicorn python-multipart httpx anthropic --break-system-packages` and `npm install playwright fake-indexeddb --no-save` as needed — this sandbox starts clean each session, nothing persists.
- Throwaway Playwright/test harnesses (this session: `fly_to_test.mjs`, `leech_banish_test.mjs`, `onboarding_audio_test.mjs`, all under a scratch `verify_scratch/` directory) deleted before each commit, per the project's standing convention — scaffolding, not shipped product. The permanent dev tools (`motion-test.html`, `test_motion_engine.py`, `test_mind_map_engine.py`, `test_motion_frontend.mjs`, and the new `test_motion_player_audio.mjs`) are real, committed, reusable test surfaces — the distinction matters.
- PAT reused across the whole session per John's stated preference, embedded in the remote URL only for each actual `git push`, scrubbed back to plain HTTPS immediately after every single push, no exceptions.
